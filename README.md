# VotersHub: Texas 2026

A nonpartisan candidate guide and issue alignment quiz for the November 3, 2026 Texas general election. Ballot rosters come from Texas Secretary of State Ballot Certification Reports. Collin County is fully loaded. Other counties can be added from their own reports (see [docs/ADDING_A_COUNTY.md](docs/ADDING_A_COUNTY.md)), and voters in counties not yet loaded see the statewide races.

## Features

- **Accounts.** Anyone can browse the guide. Taking the quiz requires a free account: email and password, or Continue with Google or Apple, plus name, county, and age range. Passwords are hashed with scrypt, common passwords are rejected, new accounts get a welcome email, and forgotten passwords are reset through a one-time emailed link.
- **Issue Quiz.** Signed-in visitors answer 31 issue statements and rate how important each one is. Results show a match percentage for every candidate on their county ballot and an alignment score with each party's official Texas platform. Results are saved with a timestamp, emailed, cached on the device, and shareable.
- **Candidates.** Every race, grouped by level and filtered by county. Each race page compares its candidates side by side (office duties, priorities, promises, record, documented positions, numbered sources). Each candidate also has a profile page.
- **Compare by Issue.** Choose an issue from a dropdown or type any word to see every candidate's documented position.
- **My Ballot.** A mock ballot in official ballot order. Voters star the races and candidates they care about to build a shortlist, mark a choice in each race, and print either the shortlist or every choice. Saved in the browser, and to the account when signed in.
- **My Account.** Every saved quiz attempt with timestamps, profile and password settings, sign out, and deleting the account and all of its data.
- **Methodology, Terms of Use, and Privacy Policy** pages.

## Running locally

Requires Node.js 22.13 or newer.

```bash
npm install
cp .env.example .env      # optional; everything has a local default
npm run dev               # http://localhost:3000, restarts on changes
npm test                  # scoring, import, and API security tests
npm run lint
```

Locally, data is stored in a SQLite file (`storage/votershub.db`) using Node's built-in `node:sqlite`, so there are no native modules to compile. Without SMTP settings, emails are saved to `./outbox/` as HTML files.

## Deploying to Vercel

A click-by-click guide for Supabase, Resend, and Vercel is in [docs/DEPLOYING.md](docs/DEPLOYING.md). In short:

1. **Create a Postgres database.** Vercel functions have no persistent disk, so production uses Postgres. Any provider works: Neon (also available as Vercel Postgres in the Vercel Marketplace), Supabase, or another host. Copy its connection string and include `sslmode=require` for hosted databases. Tables are created automatically on first use.
2. **Choose an email provider** with SMTP access, such as Postmark, Resend, SendGrid, Amazon SES, or Mailgun. Verify your sending domain with the provider so messages are not marked as spam.
3. **Import the GitHub repository in Vercel.** Leave the framework preset as "Other". `vercel.json` already sets the build command (`npm run build`), the output directory (`client`), the API function, and the security headers.
4. **Set environment variables** in Project Settings, Environment Variables:

   | Variable                                           | Required     | Purpose                                                                               |
   | -------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------- |
   | `DATABASE_URL`                                     | Yes          | Postgres connection string (for Supabase, the Transaction pooler string on port 6543) |
   | `DATABASE_CA_CERT`                                 | For Supabase | The database provider's CA certificate, so connections are encrypted and verified     |
   | `PUBLIC_URL`                                       | Yes          | Your site URL, for example `https://vote.example.org`, used in share links and emails |
   | `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | Yes          | Outgoing email                                                                        |
   | `SMTP_SECURE`                                      | No           | `true` for port 465                                                                   |
   | `MAIL_FROM`                                        | Yes          | For example `VotersHub <results@vote.example.org>`                                    |
   | `ADMIN_TOKEN`                                      | Yes          | At least 24 random characters. Unlocks the CSV exports.                               |
   | `CONTACT_EMAIL`                                    | Yes          | Corrections and privacy contact shown in the Terms and Privacy Policy                 |
   | `AUTH_SECRET`, `GOOGLE_*`, `APPLE_*`               | No           | Sign in with Google and Apple (see docs/DEPLOYING.md, Part 4)                         |

5. **Deploy.** Static pages are served from the CDN. Requests to `/api/*`, plus shared result links (`/results/<id>`, which get personalized social preview tags), run in the serverless function.

The app refuses to start on Vercel without `DATABASE_URL`, so a misconfigured deploy cannot quietly lose data.

## Collected data

The `users` table stores first name, last name, email (unique), county, age range, the update-email opt-in, and timestamps. The `quiz_results` table stores each attempt's answers, computed results, data version, share id, and timestamp. Download both as CSV:

```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" https://your-site/api/admin/users.csv -o users.csv
curl -H "Authorization: Bearer $ADMIN_TOKEN" https://your-site/api/admin/results.csv -o results.csv
```

## Updating candidate data

| File                         | Contents                                                                                 |
| ---------------------------- | ---------------------------------------------------------------------------------------- |
| `data/races.json`            | Every race and candidate, stored once even when a race spans several counties            |
| `data/ballots/<county>.json` | The races on each county's ballot, in ballot order                                       |
| `data/questions.json`        | The 31 quiz statements, each with balanced background text and the offices it applies to |
| `data/offices.json`          | What each office does, its term, and an official source                                  |
| `data/research/*.json`       | Candidate research and party platform mappings                                           |
| `data/guide.json`            | Built output served to the site                                                          |

After editing anything in `data/`, run `npm run build:data` and commit the updated `data/guide.json`. The build drops any claim that does not cite a source listed for that candidate, rejects positions outside the -2 to 2 scale, removes em and en dashes, and prints a warning for every item it drops. `npm run check:links` checks every source URL.

To add a county, run `npm run import:ballot -- report.pdf`, then `npm run research:status -- <County>` to list who still needs research. See [docs/ADDING_A_COUNTY.md](docs/ADDING_A_COUNTY.md) and [docs/RESEARCH_SPEC.md](docs/RESEARCH_SPEC.md).

## Scoring

The scoring code is in `shared/scoring.js`. For each question that both the visitor and a candidate have a position on:

```
agreement = 1 - |answer - position| / 4
weight    = importance (0.5, 1, 2) x evidence weight (1.0 record, statement, questionnaire, or platform; 0.85 reported; 0.6 inferred)
match     = (sum(weight x agreement) + 0.5 x 1.5) / (sum(weight) + 1.5)
```

The 1.5 term is a neutral prior that keeps a candidate with only one or two documented positions from showing an extreme score. Each race counts only the questions tied to that office. Matches built on fewer than three questions are labeled "limited data."
